# 服务费模式关联自动同步设计

## 概述

将宴会菜价自动同步采购和收入自动计入功能与「服务费模式」开关关联起来。开启服务费模式后，已发生的预约（今天及过去3天内）在条件满足时自动生成采购和收入记录。

## 背景

当前已实现：
- **服务费模式开关**（收费设置页）：`serviceChargeEnabled` + `serviceChargeEnabledDate`，新收入计算方式 = 菜价 + 服务费
- **宴会菜价同步采购**：预约提交时无条件自动将 `dishPrice` 同步到采购（分类=banquet）
- **收入新计算**：收入录入时已支持新模式（菜价+服务费）

问题：宴会菜价同步与开关无关，且缺少收入的自动生成。需要把两者统一到服务费模式开关下。

## 数据模型

### 采购记录（purchase 集合）新增字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `autoGenerated` | boolean | 标记为自动生成（非手动创建），默认 `true` |

### 收入记录（income 集合）新增字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `autoGenerated` | boolean | 标记为自动生成（非手动录入），默认 `true` |

### 现有字段在自动生成时的取值

**采购记录：**

| 字段 | 自动生成时的值 |
|------|---------------|
| `category` | `'banquet'` |
| `amount` | 预约的 `dishPrice` |
| `date` | 预约日期（YYYY-MM-DD） |
| `remark` | `"客人姓名 - 房间信息"` |
| `item` | 留空 |
| `purchaseBy / purchaseByName` | 当前操作用户（即时触发）/ 留空（云函数） |
| `sourceReservationId` | 关联预约 `_id` |
| `autoGenerated` | `true` |

**收入记录：**

| 字段 | 自动生成时的值 |
|------|---------------|
| `type` | `'dining'` |
| `amount` | `dishPrice + serviceCharge`（中午或晚上对应服务费） |
| `date` | 预约日期（YYYY-MM-DD） |
| `source` | 预约的 `customerName` |
| `reservationId` | 关联预约 `_id` |
| `remark` | 留空 |
| `collectedBy / collectedByName` | 当前操作用户（即时触发）/ 留空（云函数） |
| `calcMode` | `'dishPrice'` |
| `dishPrice` | 预约的 `dishPrice` |
| `serviceCharge` | 对应时段的服务费金额 |
| `guestCount / standard / roomName` | 同步自预约 |
| `autoGenerated` | `true` |

## 功能设计

### 1. 新增云函数 `autoSyncReservation`

**路径：** `cloudfunctions/autoSyncReservation/`

**配置：** 每日 23:00 定时触发

**触发器配置（config.json）：**
```json
{
  "triggers": [
    {
      "name": "dailySync",
      "type": "timer",
      "config": "0 0 23 * * * *"
    }
  ]
}
```

**核心逻辑：**

```
每天 23:00 执行：
1. 读取 settings 集合，获取：
   - serviceChargeEnabled
   - serviceChargeEnabledDate
   - serviceChargeNoon
   - serviceChargeNight
2. 如果服务费模式未开启（!serviceChargeEnabled），跳过当天处理
3. 计算日期范围：从今天往前推3天（含今天，共4天）
4. 查询这些日期内 status=confirmed、dishPrice>0 的所有预约
5. 对每个预约，检查 serviceChargeEnabledDate：
   - 如果 预约日期 < serviceChargeEnabledDate，跳过（开关生效前不生成）
6. 生成采购记录：
   - 检查 purchase 集合中 category='banquet' AND sourceReservationId=预约Id 的记录（不论 autoGenerated）
   - 如果已存在任何关联的宴会菜价记录，跳过（避免与手动录入重复）
   - 不存在则创建：amount = dishPrice，category = 'banquet'，autoGenerated = true
7. 生成收入记录：
   - 检查 income 集合中 reservationId=预约Id 的记录（不论 autoGenerated）
   - 如果已存在任何关联记录，跳过（避免与手动录入重复）
   - 不存在则创建：amount = dishPrice + serviceFee（根据时段取中午/晚上服务费）
   - type = 'dining'，autoGenerated = true
   - 同步 guestCount / standard / roomName / dishPrice / serviceCharge / calcMode
8. 标记预约 hasIncome = true
```

**幂等性保障：** 每次执行前检查是否已有 `autoGenerated=true` 的记录，已有则跳过，确保重复执行不会产生重复记录。

### 2. 预约提交时即时触发（reservation-add）

在 `reservation-add/index.js` 中修改现有 `syncBanquetPurchase()` 并新增 `syncIncome()`。

#### 门控条件

```
shouldSync(date):
  1. 加载 serviceChargeEnabled、serviceChargeEnabledDate
  2. 如果 !serviceChargeEnabled → 不同步
  3. 如果 date < serviceChargeEnabledDate → 不同步
  4. 如果 dishPrice <= 0 → 不同步
  5. 返回 true
```

#### 创建预约时

```javascript
async onSubmit() {
  try {
    // ... 现有保存逻辑 ...
    
    if (this.data.isEdit) {
      // 编辑模式
      await db.updateDoc(COLLECTIONS.RESERVATION, this.data.id, docData)
      
      // 门控检查：是否满足同步条件
      if (await this.shouldSync(docData.date)) {
        const hasDishPriceChanged = docData.dishPrice !== oldDishPrice
        const hasRemarkChanged = docData.customerName !== oldCustomerName || docData.roomName !== oldRoomName
        
        if (hasDishPriceChanged || hasRemarkChanged) {
          if (isPastDate(docData.date)) {
            // 过去日期 → 弹窗确认
            await this.showSyncConfirmDialog()
          }
          await this.syncBanquetPurchase(docData, this.data.id)
          if (hasDishPriceChanged) {
            await this.syncIncome(docData, this.data.id)
          }
        }
      }
      // ... 后续 ...
    } else {
      // 新建模式
      const result = await db.addDoc(...)
      
      if (await this.shouldSync(docData.date)) {
        await this.syncBanquetPurchase(docData, result._id)
        await this.syncIncome(docData, result._id)
      }
    }
  }
}
```

#### syncBanquetPurchase 修改

在现有逻辑基础上加入：
- 写入 `autoGenerated: true`
- 不删除非 `autoGenerated` 的记录（手动创建的保留）
- 编辑时如果 dishPrice 没变但客户名/房间变了，只更新 remark

#### syncIncome 新增

```javascript
async syncIncome(docData, reservationId) {
  const dishPrice = Number(docData.dishPrice) || 0
  if (dishPrice <= 0) return

  // 计算服务费
  const charge = docData.time === '中午' ? this.serviceChargeNoon : this.serviceChargeNight
  const amount = dishPrice + charge

  // 查找已有的 autoGenerated 收入记录
  const existing = await db.queryAll(COLLECTIONS.INCOME, {
    reservationId: reservationId,
    autoGenerated: true
  })

  const incomeData = {
    type: 'dining',
    amount: amount,
    date: formatDate(docData.date),
    source: docData.customerName || '',
    reservationId: reservationId,
    remark: '',
    collectedBy: userInfo._id || '',
    collectedByName: userInfo.name || '',
    calcMode: 'dishPrice',
    dishPrice: dishPrice,
    serviceCharge: charge,
    guestCount: docData.guestCount || 0,
    standard: docData.standard || 0,
    roomName: docData.roomName || '',
    autoGenerated: true
  }

  if (existing.data && existing.data.length > 0) {
    await db.updateDoc(COLLECTIONS.INCOME, existing.data[0]._id, incomeData)
  } else {
    await db.addDoc(COLLECTIONS.INCOME, incomeData)
    // 标记预约 hasIncome
    await db.updateDoc(COLLECTIONS.RESERVATION, reservationId, { hasIncome: true })
  }
}
```

#### 编辑过去预约的弹窗确认

```javascript
showSyncConfirmDialog() {
  return new Promise((resolve, reject) => {
    wx.showModal({
      title: '同步确认',
      content: '该预约已有采购和收入记录，修改将同步更新，是否继续？',
      success: (res) => {
        if (res.confirm) resolve()
        else reject(new Error('用户取消同步'))
      }
    })
  })
}
```

### 3. 取消/删除预约时的关联清理

**reservation-detail 的取消操作：** 删除关联的 `autoGenerated=true` 采购和收入记录。

**reservation-add 的删除操作：** 同上。

取消预约时：
```javascript
// 删除 autoGenerated 采购记录
const purchases = await db.queryAll(COLLECTIONS.PURCHASE, {
  sourceReservationId: reservationId,
  autoGenerated: true
})
for (const p of (purchases.data || [])) {
  await db.deleteDoc(COLLECTIONS.PURCHASE, p._id)
}

// 删除 autoGenerated 收入记录
const incomes = await db.queryAll(COLLECTIONS.INCOME, {
  reservationId: reservationId,
  autoGenerated: true
})
for (const inc of (incomes.data || [])) {
  await db.deleteDoc(COLLECTIONS.INCOME, inc._id)
}
```

注意：只删除 `autoGenerated=true` 的记录，手动创建的保留。

### 4. 手动创建宴会菜价采购时关联预约

在采购新增页（`purchase-add`）中，当用户选择分类为「宴会菜价」时，增加预约关联功能，类似收入新增页的关联预约选择器。

#### 交互流程

1. 用户在采购新增页选择分类为「宴会菜价」
2. 页面出现「关联预约」选择器，列出：
   - 今天及过去30天内的预约
   - `status=confirmed`
   - 尚未有宴会菜价采购记录关联的预约（检查 purchase 中 category='banquet' 且 sourceReservationId=预约Id 的记录不存在）
3. 用户选择一个预约后，自动填入：
   - 金额（`amount`）= 预约的 `dishPrice`
   - 日期 = 预约的日期
   - 备注（`remark`）= `"客人姓名 - 房间信息"`
   - `sourceReservationId` = 预约 `_id`
4. 金额、日期、备注仍允许用户手动修改覆盖
5. 当用户切换分类为非「宴会菜价」时，隐藏关联预约选择器，清除 `sourceReservationId`

#### 提交时的数据

手动创建的宴会菜价采购记录不设 `autoGenerated`（或设为 `false`），云函数判断时通过 `sourceReservationId + category='banquet'` 找到此记录，避免重复生成。

### 5. 完整逻辑矩阵

| 场景 | 采购行为 | 收入行为 | 弹窗 |
|------|---------|---------|------|
| 创建将来预约（date > 今天） | 不生成 | 不生成 | 无 |
| 创建今天/过去预约（date <= 今天） | 即时生成 | 即时生成 | 无 |
| 编辑预约，dishPrice 变化 | 更新金额+备注 | 更新金额 | 仅过去日期 |
| 编辑预约，dishPrice 不变但客户/房间变 | 更新备注 | 不更新 | 仅过去日期 |
| 编辑预约，无相关字段变化 | 不更新 | 不更新 | 无 |
| 取消/删除预约 | 删除 autoGenerated | 删除 autoGenerated | 无 |
| 手动新建采购分类=宴会菜价 | 关联预约+自动填充 dishPrice | 不涉及 | 无 |
| 云函数 23:00 | 补缺失的（跳过已有关联的） | 补缺失的（跳过已有关联的） | 无 |

## 注意事项

- 云函数幂等：检查 `category='banquet' AND sourceReservationId=预约Id` 是否存在来避免重复生成，保护手动录入的数据
- 即时触发（预约提交时）只操作 `autoGenerated=true` 的记录，不会覆盖或删除手动创建的记录
- 手动创建的采购/收入记录不受自动同步影响，不会被删除或覆盖
- 云函数同时处理采购和收入，任一失败不影响另一方
- 弹窗确认仅在编辑过去日期的预约时出现，今天预约无声同步
- 如果服务费开关是关闭状态，所有自动同步都不触发（包括云函数和即时触发）
- 取消或删除预约时只清理 `autoGenerated=true` 的记录
- 手动创建宴会菜价采购时，通过 `sourceReservationId` 关联预约，云函数会自动跳过
